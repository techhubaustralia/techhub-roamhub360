# 11 · Testing Guide

## Test stack

- **Unit / integration:** **Vitest 4** (`vitest.config.ts`). 29 test files (see below). Server-only
  modules are testable because `vitest.config.ts` aliases `server-only` → `test/stubs/server-only.ts`.
- **E2E:** **Playwright** (`playwright.config.ts`, specs in `e2e/`). One spec today: `e2e/booking.spec.ts`.
- **API regression:** `tests/api-regression.test.ts` (run via Vitest).

## Commands

```bash
npm test                 # vitest run — all unit/integration tests
npm run test:watch       # vitest watch
npm run test:api         # vitest run tests/api-regression.test.ts
npx vitest run <path>    # a single file, e.g. npx vitest run lib/booking-rules.test.ts
npx tsc --noEmit         # type-check (part of the "green" gate)
npm run lint             # eslint (flat config) — expect 0 errors
npm run build            # next build (production build gate)
npm run audit:ci         # npm audit --omit=dev --audit-level=high  → expect 0 high/critical

# E2E (needs a running app + playwright installed)
npm i -D @playwright/test && npx playwright install   # first time on a new machine
E2E_BASE=http://localhost:3000 npm run test:e2e
```

## Continuous integration (`.github/workflows/ci.yml`, added 2026-09-17)

Every push to `main` and every pull request runs three jobs on GitHub Actions (Node 22, same as the
container): **quality** (`tsc` → lint → unit tests → `next build`), **live-suite** (starts `next dev`
with placeholder secrets, waits for `/api/health`, runs `tests/api-regression.test.ts` — the 31 live
tests, file backend, no database) and **audit** (`npm run audit:ci`, advisory-only so a fresh upstream
CVE can't block a fix). Nothing in CI deploys; the droplet is still updated by hand. If a job fails,
the run's log shows the same output you'd see locally; the live-suite job prints the dev-server log
on failure.

## Simulating identities in the API regression suite

The live suite needs to act as different users and roles (one-desk rule, admin-vs-owner cancel,
staff RBAC, tenant isolation). It sends three **dev-only** headers: `x-dev-user: <email>`,
optionally `x-dev-role: global-admin | site-admin | staff` (default **staff**), and optionally
`x-dev-tenant: <slug>` = the workspace that user *belongs to* (default: the request's own tenant).
They are honoured solely by the no-session dev branch of `getUser()` (`lib/server/auth.ts`) and
parsed by the pure `devIdentityFromHeaders()` in `lib/authz.ts`, which is unit-tested to return
`null` under `NODE_ENV=production` — so they can never work against the container. No `x-dev-user`
= the base dev identity (demo workspace admin **and** platform operator), used for seeding
buildings and admin actions; a named user is never a platform operator. The *request's* tenant
comes from the Host, so the suite targets a second workspace with `x-forwarded-host:
<slug>.roamhub360.com` (what the reverse proxy sets in production). The dev branch applies the
same membership guard as a real session: a simulated member of another workspace is anonymous on
this one. The suite cancels every booking it made and deletes its `qa-*` buildings in `afterAll`,
so re-runs are idempotent.

## Current coverage & gaps

- **Strong:** pure business rules + security helpers.
- **Weak/absent:** end-to-end HTTP route tests, browser E2E breadth (only one booking spec),
  Microsoft-integration paths (Graph/Teams/Entra — mocked or skipped), DB-backed flows (no test DB in CI).
- **No coverage report** is generated by default (add `vitest run --coverage` if needed).

## Known failing / skipped tests

- No *failing* tests on the last run (green gate). Skipped tests are intentional (require DB/Graph/Teams
  runtime). If a test fails after `npm ci` on a new machine, first check Node version (target **20**),
  then that `server-only` stub alias resolves.

## Reproducing bugs

- **Timezone (H7) regression:** `lib/booking-rules.test.ts` asserts `todayInTz()`/`nowInTz()` fall back
  to `DEFAULT_TZ`, never server-UTC. Reproduce a tz bug by setting `APP_DEFAULT_TZ` and checking a
  building with no `plan.tz`.
- **SSRF (C2):** `lib/server/ssrf.test.ts` covers private-IP / redirect blocking.
- **AI guardrails (M8):** `lib/assistant-policy.test.ts` fails if a mutating tool is added or a safety
  clause is removed from the system prompt.
- **Booking rules:** most booking edge cases are reproducible as pure unit cases (no server needed).
